

## Plan: Friday-only competitions + Preparing state on non-Fridays

### Problem
`useCompetition` auto-creates a competition on every visit by calling `generate-theme`. On non-Fridays, visitors see "Submissions open" instead of a preparing/countdown state.

### Changes

#### 1. `src/hooks/useCompetition.ts` — Only create competitions on Fridays
- In `fetchCompetition`, check if today is Friday (UTC day === 5)
- If not Friday: skip `generate-theme` call, just query for the most recent past competition (for archive display) and return null for active competition
- If Friday: keep current behavior (check for today's comp, create if missing)

#### 2. `src/pages/Index.tsx` — Handle null competition gracefully
- When `competition` is null and not demo mode, force `preparing` phase
- Show preparing UI with countdown to next Friday 09:00 CET
- Update theme fallback text: `"The next ritual begins Friday at 09:00"` instead of `"Loading..."`

#### 3. `src/lib/phases.ts` — Fix `getNextFriday` for "today is Friday" case
- Current logic: `(5 - day + 7) % 7 || 7` always skips to *next* Friday even if today is Friday
- Fix: if today is Friday and it's before reveal time (15:00 UTC), return today; otherwise next Friday

#### 4. `supabase/functions/generate-theme/index.ts` — Add Friday guard
- At the start of the function, check if today is Friday
- If not, return 400 with message "Rituals only happen on Fridays"
- Prevents accidental competition creation via direct function calls

### About the AI-generated theme
The theme is generated by Gemini using the prompt in `generate-theme`. It asks for "topical, sharp, slightly unhinged" themes referencing "current cultural moments, tech trends, internet culture." The AI model has training data knowledge — it won't know breaking news from today, but it will produce culturally relevant, funny themes based on broader trends. Each Friday gets a unique theme. You can't preview it in advance since it's generated on-the-fly, but the prompt ensures it'll be sardonic and internet-native.
